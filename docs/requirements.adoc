== Epic: Dice Mechanics and Herd Growth

[cols="1,2,2,2", options="header"]
|===
|ID |User Story |Acceptance Criteria |Status

|US-01
|As a *player* I want to *roll two 12-sided animal dice* so that I can *start my turn and see the roll result*.
a|
* The system rolls two independent 12-sided dice.
* Each die returns an animal or predator symbol according to the game configuration.
* The result of both dice is visible to the player.
* The roll result can be passed to herd breeding and predator handling mechanics.
|Backlog

|US-02
|As a *player* I want to *receive newly born animals based on the roll result and the current herd* so that I can *see my herd grow*.
a|
* The system adds animals of the same species rolled on the dice to the player's current herd.
* For each full pair, the player receives one new animal of that species.
* Animals are added only when the combined total from dice and herd forms at least one full pair.
* The herd state is updated after the growth calculation.
* Unit tests verify the herd growth algorithm for different initial states.
|Backlog

|US-03
|As a *player* I want to *see a summary of herd changes after the roll* so that I know *which animals were added or lost*.
a|
* After the turn, the system shows a list of herd changes.
* The player can see the herd state before and after the roll is resolved.
* If no changes occurred, the system shows an appropriate message.
|Backlog

|US-04
|As a **system** I want to *roll results* from two 12-sided dice with different animal distributions so that *randomness is preserved*.
a|
* Two separate face sets are defined for Die 1 and Die 2.
* The roll function returns the animals from both dice independently.
* The logic handles cases where predator symbols (fox/wolf) appear on the faces.
| Backlog

|US-05
|As a *player* I want to *have a saved record of my current herd state* so that the *system can calculate future turns correctly*.
a|
* The system stores the number of rabbits, sheep, pigs, cows, horses, and dogs.
* The herd state is updated after rolls, trades, and predator attacks.
* The system never allows a negative animal count.
|Backlog
|===

== Epic: Market Exchange

[cols="1,3,4,1", options="header"]
|===
|ID |User Story |Acceptance Criteria |Status

|US-06
|As a *player* I want to *trade animals according to a fixed price list* so that I can *strategically grow the farm*.
a|
* The system supports the rate: 6 rabbits = 1 sheep.
* The system supports the rate: 2 sheep = 1 pig.
* The system supports the rate: 3 pigs = 1 cow.
* The system supports the rate: 2 cows = 1 horse.
|Backlog

|US-07
|As a *player* I want to *trade animals in both directions* so that I can *react flexibly to the game state*.
a|
* The system allows trading animals from a lower tier to a higher tier.
* The system allows trading animals from a higher tier to a lower tier.
* After the trade, the herd state is recalculated correctly.
|Backlog

|US-08
|As a *system* I want to *check whether the player has enough animals for a trade* so that I can *prevent invalid game states*.
a|
* The trade is blocked if the player does not have the required number of animals.
* The system shows a message about insufficient resources.
* A failed trade does not change the herd state.
|Backlog

|US-09
|As a *player* I want to *preview a trade before confirming it* so that I can *avoid accidental decisions*.
a|
* The system shows which animals will be removed.
* The system shows which animals will be added.
* The player can confirm or cancel the trade.
|Backlog

|US-10
|As a *system* I want to *execute the trade atomically* so that *no partially updated herd state is created*.
a|
* The trade ends with either full success or full rollback.
* In case of an error, the herd state remains unchanged.
* Tests cover both valid and invalid trade scenarios.
|Backlog
|===

== Epic: Predators and Defense

[cols="1,3,4,1", options="header"]
|===
|ID |User Story |Acceptance Criteria |Status

|US-11
|As a *player* I want the *fox to attack my rabbits* so that the game contains *an element of risk*.
a|
* If the fox appears, the system resolves an attack on rabbits.
* If the player has no appropriate defense, rabbits are lost according to the game rules.
* After the attack, the system updates the herd state.
|Backlog

|US-12
|As a *player* I want to *use a small dog to defend against the fox* so that I can *protect my rabbits from being lost*.
a|
* If the player has a small dog and the fox appears, rabbits are not lost.
* After the defense, the small dog is removed from the herd.
* The system shows a message about the small dog being used.
|Backlog

|US-13
|As a *player* I want the *wolf to attack my herd* so that *larger animals are also exposed to risk*.
a|
* If the wolf appears, the system resolves an attack on the herd.
* The horse is not lost during a wolf attack.
* The remaining animals are removed according to the project rules.
|Backlog

|US-14
|As a *player* I want to *use a big dog to defend against the wolf* so that I *do not lose animals during the predator attack*.
a|
* The system detects the wolf attack after the dice roll.
* If the player has a big dog, the wolf attack is blocked.
* After the defense, the big dog is removed from the herd.
* If the player does not have a big dog, the system resolves the wolf attack according to the game rules.
|Backlog

|US-15
|As a *system* I want to *resolve cases where more than one special effect appears in a single turn* so that I can *avoid rule ambiguity*.
a|
* The system has a defined order of effect resolution.
* Fox and wolf attacks can be handled in the same turn.
* The final herd outcome is deterministic and testable.
|Backlog
|===


== Epic: Victory Conditions and Game Flow

[cols="1,3,4,1", options="header"]
|===
|ID |User Story |Acceptance Criteria |Status

|US-16
|As a *player* I want to *start a new game with an empty or default herd* so that I can *begin from a defined starting state*.
a|
* The system creates a new game session.
* Each player receives an initial herd state according to the game configuration.
* The initial state is visible to the player.
|Backlog

|US-17
|As a *player* I want to *take my turn in a defined order* so that the game remains *clear and rule-compliant*.
a|
* A turn starts with the dice roll.
* The system then resolves predators.
* The system then resolves breeding.
* The player may trade according to the project rules.
|Backlog

|US-18
|As a *player* I want to *be informed when the victory condition is met* so that I know *when the game ends*.
a|
* The system checks the herd state after each turn.
* The system detects whether the player has the required set of animals.
* When the victory condition is met, the system shows a final message.
|Backlog

|US-19
|As a *player* I want to *see the history of recent actions* so that I can *review the course of the game*.
a|
* The system records the latest dice roll.
* The system records completed trades.
* The system records predator attacks and dog usage.
|Backlog
|===
