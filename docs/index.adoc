== Project Overview

This documentation describes the goals, scope, and implementation approach for the digital version of the "Farmer" board game.

=== Project Goal

The goal of the project is to move the core "Farmer" mechanics into a digital environment, provide a stable development setup, and maintain production-grade AsciiDoc documentation.

=== Scope

- Implementing the game logic (dice rolls, herd growth, predators, trading).
- Preparing the project infrastructure: repository, CI/CD, and documentation hosting.
- Keeping visual assets in a separate module or repository submodule.

=== Documentation Audience

- Developers
- Analysts and game designers
- Technical writers and DevOps contributors


== Architecture and Technology

This section summarizes the target architecture and the main technology choices.

=== Overview

The system should be modular and easy to test. The recommended application layers are:

- Frontend: a responsive web application built with an SPA framework.
- Backend: a lightweight REST/GraphQL service responsible for game logic and persistence.
- Database: a relational or NoSQL store depending on scalability needs.
- CI/CD: GitHub Actions for build, tests, documentation generation, and GitHub Pages publishing.

=== Implementation Notes

- The game logic should be isolated as a reusable library such as `game-engine`.
- API contracts should be versioned.
- Visual assets should live in a separate Git submodule to allow independent maintenance.

=== Non-functional Requirements

- Automated unit and integration tests.
- Documentation generated from AsciiDoc and deployed automatically.
- Monitoring and alerts integrated with Microsoft Teams.
